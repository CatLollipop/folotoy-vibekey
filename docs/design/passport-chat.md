# Passport标准聊天流

## 已确认的方向

用户选择第一版标准聊天气泡流。只改Passport的电脑会话视图，Mac保留设置页结构。消息按本次Mac运行中实际收到和设备确认发出的顺序上下排列；不主动拉取原会话历史，不声称展示原应用完整历史。

assistant左侧使用当前所选宠物的迷你头像和暗色气泡；user右侧使用柔和绿色气泡。实时ASR与未发草稿是流尾同一条右侧“草稿”气泡，不设置固定底栏。确认以后同一local ticket更新提交/排队/接纳状态，未知或失败不能冒充已发送。普通状态仍为紧凑动画图标，不恢复大面积底部提示或时间栏。

## 阅读与确认

UP/DOWN按屏查看聊天窗口；阅读旧内容时固定消息身份与原文UTF-8偏移，新消息只更新提示。显式回到最新或录音意图才跟随底部。草稿不在当前可见窗口时，短OK只能回到最新，不能发送看不到的文字。长持OK采音、松开只stage、另一次短按确认，及通知首击绑定/双击跳转保持互斥。

任务完成通知是导航：定位已观察的原消息，不把通知正文再插成一条assistant回复。未取得正文或原生定位信息时，只能回到该会话当前可得内容。原会话工具批准仍在原应用处理。

## 几何与预算

240×320，24px状态栏；聊天窗x21…218、y50…293，共198×244px。左头像20px、间距4px；气泡最多168px，正文156px，既有12px Noto字形、每行13个保守全角标量、18px行高。气泡上下共12px padding，user/draft首片段增加18px真实状态行，片段间8px。短气泡按实际字体宽度收紧，保持左右对齐。

Mac保存有界消息与阅读锚点；设备只接收最多4个128B片段。长消息使用稳定消息ID及head/tail续接，不把每段当新消息。历史淘汰与单条截断明确标记，未发草稿及未知票据独立保护。读消息与新窗口原子提交，不允许半窗、失配草稿版本或旧屏幕按键改变消息目标。

## 验证边界

使用生产LVGL及真实字体的合成内容检查中文、ASCII、组合Unicode、短/长消息、无历史、草稿、排队、未知、新消息提示、菜单/通知覆盖与恢复。模拟图不是实机照片，纯模型检查不代替实际USB/物理按键和官方原会话投递验收。0.7发布资产保持原样，新实现作为下一版交付。
